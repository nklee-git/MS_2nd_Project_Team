## 0. 이 문서가 왜 필요한가
지금까지 확정된 크로스커팅 계약(`ReorderRecommendation` 7필드)만으로는 실제 화면(대시보드)을 만들다 보니 부족한 부분이 몇 개 드러났고, 프론트가 React → ASP.NET Core MVC로 바뀌면서 데이터 연동 방식도 다시 정해야 하는 상황이야. 아래 순서대로 확인해줘 — **1번(블로킹)이 제일 급함**.

## 1. 먼저 확인/결정할 것 (블로킹)

### 1-1. Dataverse 초대 수락 여부
[[13. 팀 온보딩 체크리스트]] 기준 최민·현제 중 1명만 초대 수락 완료된 상태야. 본인이 아직이면:
- [make.powerapps.com](https://make.powerapps.com) 학교 M365 계정으로 로그인 → 우측 상단 환경에서 **"이나경의 환경"** 선택 → 왼쪽 "테이블" 메뉴에 기본 테이블(Account·Contact 등)이 보이면 성공.

### 1-2. 백엔드 아키텍처 — 본인 아이디어부터 정리해서 알려줘
저번에 "백엔드 관련해서 생각이 있다"고 했었는데, 구체적으로 뭘 염두에 둔 건지부터 알아야 스키마·연동 방식을 확정할 수 있어. 특히 이거 하나만 답해주면 됨:

> **프론트(ASP.NET Core MVC)가 데이터를 가져올 때, Dataverse Web API를 직접 호출하게 할 거야, 아니면 그 사이에 별도 C# Web API 서버를 하나 두고 싶은 거야?**

- 직접 호출이면: Security Role만 잘 세팅하면 끝, 추가 서버 불필요.
- 별도 API면: ASP.NET Core Web API 또는 Azure Functions 중 어느 쪽인지, 왜 그렇게 하고 싶은지(성능/보안/로직 캡슐화 등) 이유도 같이 — 크로스커팅 계약(1-3절 데이터 흐름 순서)에 새 컴포넌트가 추가되는 거라 문서에 반영해야 함.

## 2. `ReorderRecommendation` 스키마 확장 — Yes/No만 정해줘

기존 확정 7필드(`sku_code`/`predicted_demand`/`recommended_qty`/`risk_score`/`status`/`created_at`/`approved_by`)는 안 건드림. 아래 4개만 결정하면 됨 — 대시보드 실제 구현하면서 필요한 걸 확인한 목록이야.

| # | 항목 | 왜 필요한가 | 결정 |
| --- | --- | --- | --- |
| 1 | `resolved_at` (DateTime) | 승인/반려 처리 시각 — "오늘 승인 건수" 같은 집계에 필수 | [ ] Yes / [ ] No |
| 2 | `rejection_reason` (Text) | 이미 기능명세서에 "Azure 인프라 롤이 Week 0에 확장 설계"로 최민님 담당 지정돼 있던 항목 | [ ] Yes / [ ] No |
| 3 | SKU 마스터를 별도 Dataverse 테이블로 분리할지 | 지금 대시보드는 `style_name`/`category_code`/`color_code`/`size`/`popularity_tier`를 CSV에서 직접 조인해서 씀. Dataverse로 가면 SKU 테이블을 따로 두고 `ReorderRecommendation`에서 Lookup으로 참조할지, 아니면 필드를 통째로 복제해 넣을지 정해야 함 | [ ] 별도 테이블(Lookup) / [ ] 필드 복제 |
| 4 | risk_score 계산 근거(`stockout_urgency`, `popularity_weight`) 저장 여부 | 상세 드로어에서 "왜 이 점수가 나왔는지" 보여주는 용도. 저장 안 하고 그때그때 계산해도 되면 스키마 안 늘어남 | [ ] 필드로 저장 / [ ] 계산만 하고 미저장 |
